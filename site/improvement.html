Improvement proposals

A review queue, not a changelog. Nothing in this table has been implemented. Each proposal states the change, what it costs, what it buys, and whether this session recommends it — so the next decision is a choice between named paths rather than an argument about an unnamed one. The recommendation column is an opinion and is labelled as one; the state column is a fact about the repository.

Choose, then build. The proposals are ordered so that the ones with no dependency come first. Three of them (S8-01, S8-05, and anything touching the market prior) are gated on an answer from Unknowns & open questions; implementing them early would mean hard-coding a threshold that nobody has agreed to.
Eight proposals, each with its dependency stated. None is implemented.
id proposal effort / risk what it buys state this session's view source
S8-01 Publish the two-estimator disagreement next to every line, and the blend underneath
The brief asks for the disagreement to be the headline confidence signal. Implement it as a column on the lines page rather than a new page: a reader choosing a game sees the spread between the two ratings before the consensus number.		 Medium — one column plus a gate that suppresses a line when the disagreement exceeds the pre-registered threshold (U-01). Adds a decision surface without adding a claim. Requires U-01 first, or the threshold is arbitrary. Ready after U-01 recommended the measurement that motivates it
S8-02 Make the injury release diff a first-class page with a stability gate
The diff works and it immediately exposed a rendering artefact. Promote it: one row per (release, player), a column for status change, and a gate that refuses to publish a status-derived pick when the two releases it used have a rejected-row count above zero.		 Low — the parsing and diffing already exist; this is presentation plus one gate. Turns a working mechanism into a trust signal. The gate is the part that matters: it stops a silently lossy extraction from moving a pick. Ready recommended the measurement that motivates it
S8-03 Read the twelve box scores and fill the quarter-score column from them
The games page has no quarters. The box-score URL is printed on every card. Reading twelve box scores closes the last provenance gap in the one-row-per-game result feed.		 Low — twelve page reads plus a parser; the shape of the box score is not yet observed, so budget one page to learn it. The result feed is the basis of settlement. A settlement stamped against a capture nobody re-read is weaker than it looks. Ready recommended the measurement that motivates it
S8-04 Retire the duplicate pins: one place where a measured constant is defined
Two HCA pins and several σ values exist across trees. Each is individually honest, but a reader cannot tell which one produced a given line. Introduce one constants file with a provenance field per constant and have every tree read it.		 Medium — touches v2..v6 build inputs; the risk is a rebuild diff on every page. Removes the class of defect where two pages quote different constants (U-09). Do it with a parity check, not by hand. Needs design for review the measurement that motivates it
S8-05 Put rotation availability on the picks page as its own column
The brief asks for it explicitly. The data exists (official status per club per game), but the replacement-minutes half needs U-05.		 Low for the status column, blocked for the minutes impact. Publishing half of it is still useful and honest if the column is labelled 'designation, minutes impact not yet modelled'. Ready (status half) recommended the measurement that motivates it
S8-06 Print the naive parlay product next to the priced one
The correlations page withholds a price when the legs are correlated. The brief asks for the price and the naive product side by side, so the cost of stacking is visible.		 Low — both numbers are already computed; one is printed, the other is suppressed. A withheld number looks like a mistake; two numbers show the arithmetic. Keep the rho band and the CI beside them. Ready recommended the measurement that motivates it
S8-07 A power calculation page for the leaderboard
Before a minimum sample is set, show what the sample can detect. 'Detect a 3-point edge at 80% power' has a number attached; '300 games' does not.		 Low — a standard formula and a chart. Makes U-08 a decision instead of an argument. Ready for review the measurement that motivates it
S8-08 Do not merge the market prior until a closing line exists
Recorded as a proposal of a negative: the highest-risk change available today is to blend toward a 'market' that is not in the repository. Add an explicit build gate that fails if a market-anchored page renders without a committed closing-line source.		 Low — one assertion in the v4/v6 gate chain. Prevents the most plausible future fabrication in this project. Ready recommended the measurement that motivates it

The two I would do first, and why

S8-02 (make the injury diff a gated surface) because it is the only proposal here that already caught a real defect during this session: the 06:45 AM release's extraction loses alternating club markers, and a build that trusted it would have moved picks for clubs that had not changed. Turning that into a gate is cheap and it prevents a class of error rather than one instance.

S8-03 (read the twelve box scores) because settlement is the one output in this system that someone will actually rely on. Every quarter row currently traces to a committed capture nobody re-read; twelve bounded page reads closes that, and the URL is already printed on every game card.

What I would not do yet

Land a market-anchored prior (S8-08 is the negative of this) and re-cut the model inputs to today's capture in one step. Both are large, both are plausible-looking, and both would make the published tree disagree with itself on dates — the exact defect the README already documents. Sequence them after the constants are unified (S8-04).

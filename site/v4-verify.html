Irregularities, in one place

Every flagged item from the v4 surfaces, so a reviewer does not have to visit five pages to find them. A blocking flag means a value is not published because it cannot be verified; a gap means something is missing but nothing false has been published in its place. None of them blocks publication, and none of them is estimated.

FlagSeverityPageWhat is wrongWhat is published insteadSrc
F-V4-01blockingInjury releasesThe injury releases are stored as transcribed text, not as the original PDF bytes: bash egress to ak-static.cms.nba.com returns HTTP 000 from this sandbox, and the page-fetch tool returns the PDF as text rather than as bytes.Every release carries its official URL, its revision stamp, the time the league index was checked, this session's retrieval stamp, and a sha256 over the transcribed text (a content hash). The original file hash is not available and is not claimed.SRC
F-V4-02gapThis pagePer-player game logs for the 11/15 and 11/16 games were not transcribed: 9 games x roughly 26 player rows was outside the capture budget of the session that read them.The committed 11/13 and 11/14 logs stand unchanged and are labelled with their own dates. Nothing is back-filled and no player row is inferred from a team sheet.SRC
F-V4-03gapSchedule flowTravel mileage is a great-circle distance over arena coordinates sourced from Wikimedia/Wikidata (P625). NBA.com publishes arena name, city and state but no coordinates, so no official coordinate source exists to check against.Every travel row is labelled THIRD-PARTY and carries the date its coordinates were read. The travel distance is never presented as an official value.SRC
F-V4-04blockingBet surfaceNo licensed odds feed is connected, so there is no market price anywhere in this repository: no edge, no stake, no Kelly fraction and no closing-line value can be computed, and the market-anchored prior's weight is undefined.The bet surface publishes 0 rows and an explicit refusal for every game, and every stake is held at 0.00 units. The gate that refused it is named on the page.SRC
F-V4-05gapLayout artefactsContinuation rows in the official PDF lose their date, time, matchup and sometimes their team cell at a page break, so those cells are not directly readable.Each affected row is keyed off the block the PDF prints it in, and the reconstruction is written into the row's own note so a reader can see that it was reconstructed rather than read. A player is never assigned a team by inference from the club they normally play for.SRC
F-V4-06gapLayout artefactsOne GSW@NOP row in the 01:00 PM release (Jimmy Butler III) prints no Current Status cell at all: only the reason is legible. In the earlier 09:15 AM release the same block lost the status column for all six rows, so five of the six are now readable and this one is not.The status is left blank and flagged on the row, and the row is counted separately from the status tally. It is never back-filled and never treated as Available.SRC
F-V4-07gapCross-day diffPOR@MIN appears under two different dates in the same release (the 11/16 and the 11/17 filing), so a date-only key would merge two distinct filings.The diff key is (date, matchup, team, player), so both filings stay distinct and each is diffed against its own earlier state.SRC
F-V4-08gapRotation availabilityRotation impact is not published as a number: the official injury report states a status and a reason, never minutes, and no matched before/after pair of games has been captured for the affected clubs.Status counts only, with production impact explicitly blank and flagged. Minutes shares and replacement shares are not invented, and the availability column names its reason instead of showing a bare dash.SRC
F-V4-09gapRelease diffThe 09:30 AM release is identical row-for-row to the 09:15 AM release.It is declared with an explicit identical_to and a basis, so it is not counted as a change and does not inflate the diff ledger.SRC
F-V4-10gapLayout artefactsThe newest official release (11/16/26 01:00 PM ET) prints no Current Status for one GSW@NOP row, so that player's status cannot be read from the official text.The status cell is left blank, the reason that IS legible is kept, and the row carries a note naming this flag. It is not inferred from the club's other rows.SRC
F-V4-11gapLayout artefactsFive GSW@NOP rows in the newest release print a legible Current Status but an empty Reason cell, so their reason cannot be read from the official text.The status is published as printed and the reason is left blank. No reason is carried over from an earlier release or written from a player's known injury.SRC
F-V4-12gapRelease diffA captured injury release is a point-in-time reading and ages within the hour: the league index publishes a new release every fifteen minutes. The committed capture stopped at 09:15 AM ET while the index already listed releases up to 01:00 PM ET, so a capture can be stale by fourteen releases without anything in the repository noticing.The release ledger now stores every release with its revision stamp, the time the index was checked, and the retrieval time, and the diff between consecutive releases is published. The gap is still possible; what changed is that the age of the newest release is printed on the page and the index is checked at read time.SRC
F-V4-13gapThis pageThe shared official finals history advances every game night, while the frozen v1 slate snapshot it was once anchored to does not. A checker that compared the two reported a category error as a look-ahead leak.The check is now anchored to the report's own declared cutoff, and the cross-tree offset is disclosed as its own line rather than being hidden or used to fail a build. The v1 tree remains a self-contained 2026-11-14 build that never reads data/raw/history.SRC

Decisions

The repository has accumulated 33 suggestions and 14 open questions across several sessions. That is more than one person can act on, and several of the items are not independent: one choice decides most of the rest. This page puts the real forks side by side, with what each one costs and what evidence already exists, so a path can be chosen before anything is built. Nothing here is implemented by being listed. A row becomes work only when its state changes to ACCEPTED.

How to read this page. Every option carries the evidence we already have and the evidence we would still need. Where an option is recommended, the recommendation is about sequence, not about ambition: the cheapest way to learn whether this model has an edge is to test it against a price, and that is not possible yet. The recommendation is therefore to buy the missing input before building more on top of a number nobody can trade.

Decision 1 — the fork everything else hangs on

No strategy on this site can pass G6, because no price exists to beat. Accuracy is measured and positive; profitability is unmeasurable by construction. Every other decision below changes once this one is made.

Why A is recommended rather than C. The expensive part of this repository is already done and measured: a leakage-tested walk-forward on 148 official finals, with the over-confidence published rather than hidden. Option C throws that away to avoid a purchase. Option A tests it. If the price test fails, C becomes correct — but it should be chosen on evidence from A, not instead of it.

Decision 2 — freshness: how much staleness is acceptable?

The live site's team table and schedule are from 2026-11-14. The current injury report is 04:15 AM ET the same day, because the 01:30 PM ET file is unreachable from this build sandbox. Final game-day statuses are exactly the input that decides a same-day bet.

Decision 3 — what counts as proof of skill?

The brief asks to remove luck and reward top strategies. Those two goals pull in opposite directions on small samples: a leaderboard published early rewards luck, because early leaders are mostly variance.

Decision 3 options
Option Path What it unlocks Cost / effort What we would still need Assessment Source
A 300 settled bets per strategy before any ranking (current G7) A 55% hit rate separates from 52.4% at 5% one-sided; rewards become meaningful. Slow: at a realistic volume this is most of a season Prices and settlement (Decision 1) RECOMMENDED nba.com/games
B Publish a provisional leaderboard with a visible uncertainty band Faster feedback and more engagement, with the luck problem stated on every row. Low to build, but it invites reading a noisy rank as a result An explicit rule that no reward is paid on a provisional rank VIABLE WITH RULE nba.com/games
C Rank on the walk-forward backtest alone, no live bets Measured today, on 148 official finals, with no settlement needed. Low, using what already exists It ranks the model, not strategies, and it cannot see prices VIABLE FOR MODEL nba.com/games

Decision 4 — how should the site present numbers it cannot stand behind?

This session found three cases where a page implied more than the data supported: an expired window presented as upcoming, a shared parameter page presented as a per-row source, and a rest table that could not see a back-to-back. All three are fixed. The question is what rule prevents the fourth.

Decision 4 options
Option Path What it unlocks Cost / effort What we would still need Assessment Source
A Blank plus a flag id on every unverifiable cell, enforced in CI The reader can see exactly what is unknown and why; a guess cannot reach the page unnoticed. Already in place: the provenance lint and the row-level checker Nothing RECOMMENDED - keep nba.com/standings
B Add an external-URL status sweep to CI Would have caught the 30 dead team links this session found, which passed every existing test. Low: a cached link checker Nothing RECOMMENDED - add nba.com/stats/teams/traditional
C Publish a plausible estimate with an explicit confidence label Fills the page and looks complete. Low, and the most attractive option on this list It is the exact failure mode the brief rules out: an invented value that reads as fact REJECTED nba.com/games

What to do first, in order

  1. Decide Decision 1. Everything else is cheaper once it is settled, and two of the four decisions below cannot be evaluated without it.
  2. Approve SG-26 (scheduled ingestion). It is the only item that fixes freshness for all inputs at once, and it needs no further design.
  3. Approve SG-32 (external-URL sweep). Lowest-cost guard against the class of defect this session found: links that exist but do not resolve.
  4. Hold SG-29 (bet log) and SG-33 (injury deltas) until 1 and 2 are through. Both are high value and both are blocked on inputs that do not exist yet.
  5. Do not promote any strategy until 300 bets have settled. The calibration slope of 0.27 says the probabilities are over-confident, so an early leader would be measuring luck.

Each suggestion above has a state on the Suggestions queue. Changing a state there is the only way an item becomes work; this page is the reasoning behind the order.

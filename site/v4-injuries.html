Injury releases

Official injury releases stored with revision and retrieval stamps, and the mechanical diff between consecutive ones, parsed by content type.

Every release is stored with three stamps and one hash. The revision time is the time printed in the release's own header; the retrieval time is when this session read it; the index check is when the official index was last consulted for a newer file. The hash is over the stored rendering of the release, not over a hand transcription, so an edit to what we read is detectable.
Why the rows below are parsed and not typed. Every cell in the diff is assigned by content type — a date, a time, a matchup, a status word, a Last, First player, a reason — and never by column position. The PDF's layout shifts across page breaks, so a positional parser mis-reads it; the previous build did exactly that and published a changed status as unchanged. A cell whose type cannot be determined is published blank and flagged. The unread column counts them: it is zero for both releases below.

The PDF bytes

The original files are not in this repository, and that is flagged as F-V4-01 rather than glossed over: bash egress from the development sandbox to ak-static.cms.nba.com is TLS-reset, so a build cannot download them. The scheduled job runs python -m nba2.v4.injury_ingest from a GitHub runner, where the CDN is reachable, and writes data/v4/injury/binary_manifest.json with the byte length and sha256 of each file it stores — or the exact error and timestamp if it could not. The build never reads those bytes as data; the published rows come from the stored rendering.

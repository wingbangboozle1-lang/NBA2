Why the nightly job fails, stated precisely

The rolling surface runs python -m nba2.v2.refresh --write, which fetches stats.nba.com/stats/leaguestandingsv3, …leaguedashteamstats and …scoreboardv3 as JSON. The committed probe shows those hosts time out or return 403 from a GitHub runner, while the same runner gets HTTP 200 for the rendered pages at www.nba.com/standings, www.nba.com/schedule, the official injury index and the gamebook PDFs. Every surface the brief requires is reachable; the transport the refresh uses for three of them is not. That is a repairable defect with a known shape — read the rendered page rather than the JSON API — and it is logged as request RQ-8892-01 on the board rather than patched here, because nba2/v2/refresh.py sits inside another finished session's scope.

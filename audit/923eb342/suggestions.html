Detail

SG-923-01 · Make the publish chain gate on a reproducible fixed point, not on freshness of a literal

Replace n_slate = 34 / wins == 188 in nba2/v2/check.py with assertions computed from the snapshot under check (games in the slate, ΣW == ΣL, every line's game id present). A gate that freezes one week's numbers blocks every later week.

Severity high · Impact: unblocks F-923-01/F-923-11

SG-923-02 · Publish the disagreement first, the blend second

On the lines page, lead with |est_a − est_b| and the agreement verdict, then the blend. The two estimators already exist; this is a template change in one table.

Severity high · Impact: satisfies F-923-09

SG-923-03 · Add a pending row class to the result feed instead of omitting the game

A game that is scheduled but not final should appear as a row with status scheduled and blank score. Then 'the feed is complete' becomes checkable, and a missing row is a defect rather than an absence.

Severity medium · Impact: fixes F-923-02 permanently

SG-923-04 · Archive the injury index on a fixed 15-minute cadence and diff consecutive releases

The index is a stable list of URLs. A daily cron that reads the index and archives every new PDF turns the 10.3% player coverage problem into a data-engineering problem instead of a research one.

Severity high · Impact: fixes F-923-04/F-923-06

SG-923-05 · Report the log-loss difference with a confidence interval, not just its sign

0.7058 vs 0.6931 over the settled sample is 27 games. Publish the interval and the number of games needed to separate the two, so a negative result cannot be read as a verdict on the model.

Severity high · Impact: resolves Q-923-05 before any strategy claim

SG-923-06 · Seal every day's lines before tip, including days with no pick

An empty-but-sealed ledger is evidence that no pick was withheld after the fact. Today the site can publish nothing for 11/19 and no one can tell whether that was a decision or a failure.

Severity high · Impact: closes F-923-12

SG-923-07 · Pin the pages configuration and delete the ambiguity

One published tree, one build, one URL. Keep the others under archive/. A reader should never have to work out which dashboard they are reading.

Severity medium · Impact: resolves Q-923-10

SG-923-08 · Add a machine-checked 'verified at' column to every published table

The rule is already 'every row carries a source'. Make it 'every row carries a source and the time it was read', and let the checkable age of each row drive the freshness banner.

Severity medium · Impact: makes freshness per-row instead of per-site

SG-923-09 · Split the site into projection/ and bet/ as two roots, not two nav groups

Nav grouping still lets a reader land on a gated page by URL. Two directories with different gates make the wall structural.

Severity medium · Impact: brief requirement, currently nav-only

SG-923-10 · Add a public 'what would change our mind' panel to each strategy

For each preregistered strategy: the sample size at which it would be declared dead, and the measurement that would revive it. This is the cheapest defence against a leaderboard that cannot lose.

Severity low · Impact: complements the existing gate matrix

How to choose

The queue is deliberately ordered so that the first two items unblock observation of everything else. A change that cannot be measured is a change that cannot be defended, and today the site cannot publish at all — so the highest-value work is the least interesting work.

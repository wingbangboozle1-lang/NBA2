Q-24 Is a 4-game, 0-loss forecast worth publishing at all, and what is the minimum n before a strategy may be ranked? The first real out-of-sample result in the repository: nba2/data/picks.json committed 83 minutes before tip, 4 distinct games bet, all 4 won (S1 moneyline and S2 spread fired on the same games, so 8 recorded wins are 4 games). Model called the winner in 5 of 9 games; always-home would have got 7. The promotion threshold. Existing gates want 30 settled bets, which is the right order of magnitude but has never been ratified as a number the owner will accept waiting for. Owner ratifies: minimum n (proposal: 100 settled, to have power to detect a 3-point edge), and whether a 4-0 start is allowed to be displayed at all once n is known to be inadequate. 4-0 is exactly the result that would get a bettor to increase stakes. Publishing it without the n=4 context would make the site a machine for manufacturing false confidence. HIGH derivedCOORDINATION.md FLAG-QUEST-01
Q-25 Should a per-strategy win rate be allowed to count the same game twice when two strategies fire on it? The measured overlap: of 4 graded games, all 4 were bet by both S1_MarginFavorite and S2_SpreadValue. Per-strategy hit rates stay valid; any portfolio or leaderboard return that sums them double-counts the games. A portfolio accounting rule: whether the leaderboard scores strategies independently (as now) or scores the union of positions actually held. Owner decision. Independent scoring is simpler and correct for ranking hypotheses; union scoring is correct for describing what a bankroll would have done. They answer different questions and the site currently only implements one. If rewards are paid on summed per-strategy results, two correlated strategies split one result twice and the reward pool systematically overpays correlation, which is the thing the project exists to price. HIGH derivedCOORDINATION.md FLAG-QUEST-01

Q-29 Who is allowed to move the build stamp, and how should a refresh be recorded? The stamp is now derived from the newest retrieved_at_utc inside the committed snapshots (2026-11-14 01:05 UTC as of this build), so it cannot drift on a rebuild. An explicit NBA2_BUILD_STAMP override exists but nothing in CI sets it. A refresh procedure. Today a snapshot is refreshed by a human or a workflow writing a new file under data/raw with a new retrieved_at_utc; nothing records who authorised the refresh or which official page it came from at run time. Make the nightly refresh the only writer of data/raw, have it write retrieved_at_utc plus the exact source URL per file, and forbid hand edits in CI by checking that every new snapshot carries a retrieval record. The override then never needs to be used. Without it 'as of' is only as trustworthy as the last hand edit, which is the class of problem F-029 came from. MEDIUM derivedCOORDINATION.md FLAG-QUEST-01
